# 为视频分析器做贡献

感谢你为视频分析器项目做出贡献的兴趣！本指南概述了通过拉取请求（Pull Request）进行贡献的流程。

## 开始之前

1. 仔细阅读 [docs/DESIGN.md](DESIGN.md)，以了解：
   - 项目的架构
   - 核心组件及其交互方式
   - 设计决策及其理由
   - 实现细节

2. 熟悉代码库：
   - 了解项目结构
   - 理解各个模块
   - 查看现有功能和实现

## 提出变更建议

1. 在创建拉取请求之前，先在 [GitHub Discussions](https://github.com/byjlw/video-analyzer/discussions) 中发起讨论：
   - 概述你提议的变更
   - 解释变更背后的动机
   - 描述你计划的实现方案
   - 等待社区反馈和维护者的意见

2. 使用适当的讨论分类：
   - "Ideas" —— 新功能建议
   - "Q&A" —— 关于实现的问题
   - "Show and Tell" —— 分享原型

## 进行修改

在你的提案经过讨论并获得批准后：

1. Fork 仓库并创建新分支：
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. 遵循项目的编码规范：
   - 保持代码风格一致
   - 添加适当的文档
   - 包含类型提示
   - 编写清晰的提交信息

3. 为新功能添加测试：
   - 单个组件的单元测试
   - 功能工作流的集成测试
   - 确保所有测试通过

4. 更新文档：
   - 添加/更新文档字符串（docstrings）
   - 更新相关的 .md 文件
   - 如适用，添加示例

## 提交拉取请求

1. 提交之前：
   - 确保所有测试通过
   - 更新文档
   - 将你的变更添加到 CHANGELOG.md
   - 在最新的 main 分支上执行 rebase

2. 创建拉取请求：
   - 引用讨论帖
   - 提供清晰的变更描述
   - 列出任何破坏性变更
   - 包含测试步骤

3. PR 描述应包含：
   - 讨论帖链接
   - 变更摘要
   - 已执行的测试
   - 如有 UI 变更，附上截图/视频
   - 破坏性变更（如有）

## 审查流程

1. 维护者将审查你的 PR：
   - 代码质量
   - 测试覆盖率
   - 文档
   - 设计一致性

2. 处理审查反馈：
   - 按要求进行修改
   - 回复评论
   - 如需更新测试

3. 一旦获得批准：
   - 如要求，压缩提交（squash commits）
   - 确保分支是最新的
   - 等待维护者合并

## 额外指南

### 代码风格
- 遵循 PEP 8 规范
- 使用有意义的变量名
- 保持函数聚焦且简洁
- 为函数参数添加类型提示
- 为复杂逻辑添加注释

### 测试
- 为新功能编写测试
- 如需更新现有测试
- 确保测试覆盖
- 测试边界情况

### 文档
- 保持文档及时更新
- 使用清晰、简洁的语言
- 包含代码示例
- 如需更新 README.md

### 提交信息
- 使用清晰、描述性的信息
- 引用 issues/讨论帖
- 遵循约定式提交格式：
  ```
  feat: 添加新功能 X
  fix: 修复 Y 的问题
  docs: 更新贡献指南
  test: 为功能 Z 添加测试
  ```

## 获取帮助

如果你需要帮助：
1. 查看现有的 [discussions](https://github.com/byjlw/video-analyzer/discussions)
2. 如需要，发起新的讨论
3. 紧急问题可以 @ 维护者

## 开源协议

通过做出贡献，你同意你的贡献将在项目的 Apache 许可证下发布。
